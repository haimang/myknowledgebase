### 2.2 legacy-family（TypeScript / Cloudflare）数据使用

#### 2.2.1 库形态

- **D1 共享关系库**：console DDL 分文件管理 identity/teams/workflows/files/process-tracking 等；
- **Durable Object SQLite**：vectorizer 内 `buffered_vectors` WAL + `internal_tasks` 优先队列；contexter DO 内 conversation/chat 表；
- **外部 Vectorize**：向量本体不在 D1，D1/`smind_vec_process` 只作工作单元与元数据；
- **事务**：`db.batch([...])` 多语句批处理（admin 建用户、clean-dispatcher 散射 relations UPSERT）；**非**完整跨 Worker 分布式事务；
- **几乎无 SQL VIEW**：生产查询主要靠 **表 + 二级索引**；“view”多出现在 API/UI 语义而非 `CREATE VIEW`。

#### 2.2.2 表设计模式（可借鉴 / 必须删除）

| 模式 | Legacy 证据 | 借鉴 | 删除/升级 |
|---|---|---|---|
| team-centric 列 | 几乎所有业务表 `team_uuid NOT NULL` | **强制 team 作用域列与索引前缀** | 平台 users/members/billing 表不进 MKB |
| 大 JSON payload 列 | `payload_*` TEXT JSON | 允许非权威/扩展 JSON；**核心 identity/state/proof 必须晋升列** | 禁止把状态机塞进 JSON |
| 混态超级 status | `smind_files.file_status` 混合 upload/clean/rag/index/ready | — | **D02 已禁止**；MKB 分账六 StateFamily |
| 步骤追踪宽表 | `smind_clean_process` / `smind_rag_process` 平行结构 | 统一 Process 表 + capability key，而不是 clean/rag 双表 | 删除双 dispatcher 分表 |
| 向量工作单元表 | `smind_vec_process`：block_id/granularity/channel + pending 队列索引 | generation-scoped 坐标 + 队列索引思路 | 坐标升级；向量 blob 不进业务 SSOT 行 |
| 散射幂等 | `smind_files_relations` + `ON CONFLICT(team_uuid, atomic_id)` | **复合幂等键 + UPSERT** | atomic_id 升级为 Intake ExternalKey 语义 |
| 二级索引策略 | `(team_uuid, …)`、status 轮询、file/job 反查、partial index（folders lock） | **租户前缀 + 状态队列 + 主体反查 + 谨慎 partial unique** | 避免无选择度的全局 status 单列索引成为唯一策略 |
| DO 内 WAL | `buffered_vectors` 先写后刷 Vectorize | outbox / 暂存再对外副作用 | 不把 DO 拓扑搬进 MKB |
| partial unique | prompts/templates `UNIQUE WHERE status=draft/active` | 版本化 registry 可用 | registry 业务归 S14，S12 只提供约束能力 |

#### 2.2.3 索引使用结论

Legacy 索引服务四类查询，MKB 必须在 S12 为已冻域提供等价访问路径：

1. **租户列表**：`team_uuid`（+ time/status）；
2. **工作队列**：`status` / `(status, available_at, priority)`（python 侧更明显）；
3. **主体反查**：`file_uuid` / `job_uuid` / `document_id`；
4. **幂等与唯一**：`(team, atomic_id)`、`(run, step_key)`、content_hash。

MKB 对应：Task `(team_uuid, task_uuid)`、Process claim 队列、Intake item/revision、Generation `(team, execution, artifact_type)` 唯一 current 等——**具体 DDL 在后续 Round，不在本轮三题抢写**。

### 2.5 Evidence verdict（设计分母）

1. **关系 SSOT + 明确事务边界** 是 MKB 相对 legacy 最大升级点（修复 callback/queue 成功、非事务 wakeup）；
2. **索引以租户 + 队列 + 主体 + 幂等** 四类为主，不靠无文档化的全表扫描；
3. **View 仅投影**；legacy-family 几乎不用 VIEW，python 用 VIEW 做 soft-delete 过滤——MKB 可采用；
4. **向量与对象** 不得反向定义业务状态；
5. **Turso beta 并发写** 正好服务 “事务中带业务/模型等待” 的 Process 模型，但必须把启用与限制写成规范；

1. 写业务状态必须通过 S12 UnitOfWork；

### Q4 — Outbox 与 Process claim/fence 的物理合同应冻结成什么形状？

- **驱动真相**：`T-O-100` / `T-O-102` / `T-O-104`（尤其 TX-03/04/07 与后置 wake）
- **单一裁决面**：关系主库内 **outbox** 与 **claim/fence** 的最小 durable 职责、重放语义、与外部 queue 的分界（不是完整列清单）
- **不在本题裁决**：具体消息总线选型（Redis/SQLite queue/内存）、完整 Process 表 DDL、S15 告警阈值、lease 秒数默认值
- **影响范围**：S03 recovery；S06/S05 事务后 wake；崩溃一致性
- **事实驱动**：legacy 非事务 wakeup；python `task_claims`；S03 fencing；TX-07 要求 outbox 与业务同事务

#### 执行方案选项

| 选项 | 摘要 | 含义 |
|---|---|---|
| **A** | 无 durable outbox：进程内 channel 即 wake | 简单；崩溃丢 wake → 依赖全表扫描补偿 |
| **B** | **Transactional outbox 表 + claim 内嵌/附属 fence 合同（推荐）** | 业务 TX 同事务写 outbox 行；提交后 dispatcher 投递；claim 以原子 CAS 占用 Process 并写入 fence/lease；stale fence 拒绝 Outcome |
| **C** | Outbox 外置独立 DB/日志系统为 SSOT | 引入第二真相源，违背 T-O-100/102 |
| **D** | 每次 wake 全表 scan ready Processes，无 outbox | 可工作但噪声大；大库下难验收 |

#### 推荐执行方案（选项 B）

1. **Outbox（关系主库内表或等价 append-only 结构）**  
   - 与触发它的业务状态 **同事务** 插入（TX-07）；  
   - 行至少逻辑包含：`outbox_id`、`team_uuid`、`topic/kind`、`payload_ref 或 typed payload`、`dedupe_key`、`created_at`、`available_at`、`attempts`、`status(pending|dispatched|done|dead)`；  
   - dispatcher **at-least-once** 投递；消费者必须幂等；  
   - 投递成功只更新 outbox 状态，**不**回写业务状态成功语义。  

2. **Claim / fence**  
   - Process 从 `ready`→`claimed` 必须原子：校验期望状态 + 写入 `claim_fence`/`lease_expires_at`/`worker_id`（可在 processes 行或 `process_claims` 附属表，二选一在 Spec 定，但 **语义唯一**）；  
   - Outcome/状态推进必须携带 **current fence**；不匹配 → 拒绝；  
   - lease 过期后 recovery 只能由 S03 语义规则抢回 `ready` 或 `failed`，S12 提供 CAS 原语。  

3. **禁止**  
   - 先发 queue 再写 outbox/业务；  
   - 把 queue ACK 当 Process success；  
   - 多 outbox SSOT（例如再引 Kafka 作为状态源）。  

4. **允许**  
   - 外部 queue 作 **传输优化**；SSOT 仍是 outbox 行；

### Q8 — Outbox 投递环与 claim lease/recovery 的最小可执行语义是什么？

- **驱动真相**：`T-O-105` / `T-O-104` / `T-O-102`
- **单一裁决面**：outbox 如何从 pending 走到 done/dead；claim lease 过期后谁能抢回；默认语义（非具体毫秒调参平台）
- **不在本题裁决**：S15 告警 UI、具体队列中间件品牌、lease 默认 30s 还是 60s 的最终数值（可给推荐默认值但允许配置）
- **影响范围**：S03 recovery、实现 worker 主循环
- **事实驱动**：at-least-once；S03 fencing；legacy restarter

#### 执行方案选项

| 选项 | 摘要 | 含义 |
|---|---|---|
| **A** | 同步在 TX 内直接调用下游函数 | 无持久 wake；崩溃丢任务 |
| **B** | **Outbox polling dispatcher + fence 保护的 claim 循环（推荐）** | 后台循环：领取 pending outbox → 投递 → 标记 dispatched/done；失败增 attempts；超限 dead。Claim：ready CAS→claimed；worker 持 fence；lease 过期后 recovery CAS 回 ready/failed |
| **C** | 仅 LISTEN/NOTIFY 或纯内存事件 | 丢持久性 |
| **D** | 外部 cron 扫全业务表无 outbox | 与 T-O-105 冲突 |

#### 推荐执行方案（选项 B）

**Outbox 环**

```text
TX commits with outbox(pending)
  → dispatcher claims outbox row (CAS pending→in_flight)  // 可选细态，或用 lease on outbox
  → deliver to in-process queue / lightweight local queue
  → on success: outbox done
  → on fail: attempts++; backoff; re-pending or dead
```

- 投递 **at-least-once**；handler 幂等（用 dedupe_key / 业务键）。  
- dispatcher 与业务 worker 可同进程（符合单发布单元）。  
- **禁止** 业务成功后不写 outbox 却依赖“函数接着跑”。

**Claim / lease**

```text
CAS process ready→claimed + set fence F + lease_expires_at
  → worker runs (may call model) with fence F
  → success: TX with fence check → terminal + outbox
  → lease expired: recovery CAS (claimed∧expired→ready or failed) per S03 rules
  → stale fence outcome: reject
```

- lease 时长 **配置项**，Spec 给安全默认（如数十秒～数分钟级，随最长 Process 类型可覆盖）；  
- heartbeat 可选：若实现，必须仍以 fence 为准。  

**与未来 queue+db fork**

- v1 用 **同进程 lightweight queue 消费 outbox** 即可；  
- 未来 fork 架构 reopen，不得在 v1 假装已支持。

#### Reasoning 与证据

- T-O-105 已要求 durable outbox；B 给出可编码的状态环。  
- S03 需要 fence；无 lease recovery 会永久卡 claimed。  
- 业主允许未来轻量队列：B 的“传输层 queue”预留了口子，但不把外部系统当 SSOT。  
- A/C/D 无法通过崩溃注入验收。

#### Owner 问题

Owner 是否接受 **选项 B**：同进程（或等价单单元）**outbox polling 投递环** + **CAS claim/fence/lease recovery**；at-least-once + 幂等；lease 可配置；v1 不强制外部队列/DB fork？

#### 业主回答
