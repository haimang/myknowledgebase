### 3.2 过去架构一句话

### 3.3 读路径（过去 · 摘要）


## 3.9 ★ Reference-Check（网络探查 · 验证 Q1–Q3 推荐 · 非 Truth）

> **日期**：2026-08-12

### 3.9.1 探查问题 ↔ 推荐映射

| 题 | 推荐摘要 | 网络验证焦点 |
|---|---|---|
| **Q1** | 硬 dual-fence 序；typed empty；team 强制；未知 filter fail-closed；无 public raw vector | 多租户隔离；元数据 filter ≠ 授权；ANN 后二次鉴权；empty HTTP 语义；embedding 敏感 |
| **Q2** | 可观测 Traceback；generation-scoped；Inflation ON+预算 | Parent/small-to-big 检索；Hit/上下文分账；预算防 context flood |
| **Q3** | topK 默认 10≤cap；threshold 配置化（默认倾向关数值门）；rerank ON；失败保留 ANN 诚实分 | 两阶段 recall→precision；阈值可调非真理；分数字段分账；禁假分 |

### 3.9.2 Q1 验证结论

| 判定 | 结论 |
|---|---|
| **推荐 B+B1 总评** | **强支持**。行业安全与多租户实践一致要求：**检索时强制 tenant/access 约束**，且 **不得** 把「ANN 命中」当作授权通过。 |
| 双层 fence | **正例**：AWS「defense in depth」——API 层 + document-level 元数据 filter **互相独立**；一层被绕过另一层仍拦。filter 构造 fail-open 会跨组泄露。 |
| 元数据 filter 不足 alone | **正例/警告**：多文强调 metadata filter 是基础但 **非完整安全策略**（权限动态、同步滞后）；应在 **retrieval time** 再验权限（对齐 S04 EligibilityPort 实时 lifecycle/serving）。 |
| 租户强制 | **正例**：Pinecone/Weaviate 多租户：query 必须带 tenant 隔离（namespace 或强制 filter）；OWASP：**tenant A 块永不可被 B 召回**。 |
| fail-closed | **正例**：AWS deny-by-default（授权服务不可用则 deny）；OWASP foundational：**Fail-closed across RAG pipeline**。未知 filter 静默忽略 ≈ 假隔离（对齐 legacy N-02）。 |
| empty ≠ error | **正例**：REST 检索/列表惯例：合法查询无命中 → **200 + empty collection**；404 用于资源不存在。AWS Layer2 deny 可落为 **empty result set**（与「无资格命中」同形）。**非法 pin / 缺 team** → 4xx 仍正确。 |
| 无 raw vector | **正例**：OWASP Embedding Privacy：embeddings **按敏感数据**；限制 top-k、阈值；**不**公开 embedding API。legacy P-03 `returnValues:false` 与行业一致。 |
| pre vs post filter | **中性/实现注记**：Pinecone 等讨论 pre/post/single-stage filtering 性能权衡。MKB 已有关系谓词 + ANN：**ANN 候选后 hard eligibility**（post）在正确性上可接受；高选择率时可推进引擎侧 pre-filter。**正确性优先于「只 ANN」**。 |
| alias / active gen | **正例**：ES/OpenSearch **read alias / blue-green** 只服务 active 索引——对齐 S09 ActiveIndexPointer；S10 默认只查 active。 |

**Q1 对推荐的微调（仍属 B 族，供业主）**

1. 文档中明确：**filter fail-open = 安全事故**（W-反例）。  
2. empty 子码建议保留 `no_hit | all_filtered | below_threshold`（可观测，非必须对外破坏兼容）。  
3. raw vector：公共面禁止；若未来 debug port，须独立 auth + 审计（OWASP）。

### 3.9.3 Q2 验证结论

| 判定 | 结论 |
|---|---|
| **推荐 B+B1 总评** | **强支持**。Parent-document / small-to-big 是 2023–2026 主流 advanced RAG 模式，与 D05 Inflation/ContextTier **同构**。 |
| 小块召回 + 大块交付 | **正例**：LangChain `ParentDocumentRetriever`：child 向量检索，返回 parent 更大上下文；LlamaIndex hierarchical / AutoMerging 同类。对齐「summary/细粒度 hit → original/g=0 payload」。 |
| 可观测失败 vs 静默 | **正例**：生产文强调 **source attribution / confidence metadata**；「合成幻觉」「版本冲突」需要调用方看见证据质量。静默 summary-as-original（legacy N-05）与 **provenance** 原则冲突。  
| per-hit fail 不整查失败 | **支持 B 非 C**：单块 hydrate 失败不应杀死跨文档查询；用 `traceback_status` 隔离（行业「partial evidence」思路）。 |
| Inflation 预算 | **正例**：OWASP context window：限制 chunk **数量与总 token**（例 3–5 chunks / 2k–4k tokens 量级作参考，非 MKB 常数）；防 context flooding / prompt injection 面。超预算须 **可观测 drop/truncate**。 |
| generation / version 坐标 | **正例**：生产失败模式「多版本政策文档并存 → 模型混用」——检索必须钉 **serving/current generation**，不能裸 file#block。对齐 T-O-252 + S04 serving。 |

**Q2 对推荐的微调**

1. Inflation 预算默认值可用「每查询 root 条数 + 每 root 字符/token」双 cap（行业 token 思维 + legacy 字符 cap 可并存）。  
2. Result 强制带 provenance 字段（已在 D05 最小字段；RC 强化 **不得省略** `traceback_status` / `generation_refs`）。  
3. 不把 ParentDocumentRetriever 实现细节当 SSOT——只吸收 **「检索粒 ≠ 交付粒」** 产品律。

### 3.9.4 Q3 验证结论

| 判定 | 结论 |
|---|---|
| **推荐 B+B1 总评** | **强支持**（rerank 两阶段 + 诚实分数）；threshold **默认关闭数值门** 与「先标定再门控」一致，但行业 **强烈建议具备可开阈值能力**。 |
| 两阶段 retrieval | **正例**：Pinecone/NVIDIA/多文：Stage1 宽召回（bi-encoder ANN）→ Stage2 cross-encoder rerank → 截 top 送下游。Pool 常见 **20–100**，增益在 ~50–100 plateau。对齐 `k_ann ≥ return_n` 配置池。 |
| topK 默认 ~10 | **正例**：Spring AI 等 thumb：**topK 4–6 起步**；生产常 **最终 5–10** 进上下文。S09 default=10 落在行业带内。cap 防滥用与 OWASP top-k 限制一致。 |
| threshold 可调非真理 | **正例**：incomplete → 降 threshold / 升 topK；noisy → 升 threshold / 降 topK；经验区 **0.6–0.7**（cosine 域）仅作 **标定起点**。  
| 无相关则返回空 | **强正例**：生产文：**阈值后 zero hit → 不喂噪声给模型**；诚实「信息不足」优于幻觉。支持 empty 语义 +（G-07 若做 answer）拒答。  
| 假分 / 不可比分数 | **反例引导**：ANN cosine 与 rerank score **量纲不同**；Azure/Progress 等强调 **分字段分账**（`@search.score` vs `@search.rerankerScore`）。**禁止** dummy 0.5 冒充 rerank。失败应 **保留 ANN 序+ANN 分** 并标 `rerank_status=failed`。  
| 模型换代重标定 | **正例**：Pinecone/Cohere：rerank 模型迁移后 **硬编码阈值必须重调**。支持 threshold **配置化**、禁止写死 Truth 常量 0.65。 |
| fail-closed 整查询 | **弱支持 D**：rerank 失败杀全查询损害可用性；行业默认把 rerank 当 **增强层**，一阶段结果仍可服务。**推荐 B 诚实 fallback** 优于 D。 |
| 默认 rerank ON | **支持**：多源称 rerank 是生产最常见 quality lever；S11 已备本地 rerank。低延迟 profile 可 OFF（选项 C 作 profile，非默认）。 |

**Q3 对推荐的微调**

1. **明确两池参数**：`recall_k`（ANN，默认建议 20–30，≤max_topk）与 `return_k`（最终，默认 10）——RC 强化比「单一 topK」更贴近两阶段实践。  
2. 响应级建议保留 `ann_score` + `rerank_score?` + `rerank_status`（对齐 Azure 分字段）。  
3. threshold 默认 **0.0（关）** 仍合理作 v1 安全冷启动；**readiness/运维文档**应写「上线前用 golden set 标定再开」。业主若偏好 **0.60 温和门** 亦在行业带内。

### Q1 — Dual-fence 服务管道：应用顺序、空结果 vs 错误、强制过滤与 raw vector 面

  S10 必须钉：**(a)** 默认 score threshold 有无；**(b)** 查询 topK 默认与 caller override；**(c)** rerank 默认开/关、top_n 与 ANN topK 关系；**(d)** rerank 失败时 fail-open 还是 fail-closed、**禁止** dummy 假分。  
- **为什么必须确认**  
  1. 无默认策略则实现者回退 legacy 魔法数（N-09）或完全无 gate。  
  2. Rerank 断链 + dummy 0.5（N-07/N-08）使「重排」名存实亡且污染解释。  
  3. topK 与 rerank top_n 若不钉关系，会出现 cap 内仍不可控膨胀。  
  4. S11 已提供 `rerank` facade——S10 只差 **策略**，不是能力有无。

#### 选项组合

| ID | 选项 | 含义 | 与邻域 | 主要风险 |
|---|---|---|---|---|
| **A** | **Legacy 魔法包** | threshold=0.65 写死；async topK=15；rerank 总开；失败 dummy 0.5；query 可断 | 违反可观测/可配置 | 假分；不可验收 |

**推荐详细说明**

1. **topK**  
   - 请求缺省 → **10**（S09 default）。  
   - 请求提供 → clamp 到 `[1, max_topk]`；越界 **fail-loud**（与 Q1 一致）。  
2. **Score threshold**  
   - 作为 **S10 策略配置**（及可选 per-request ≤ 配置 max），在 ANN 后、fence 后或 fence 前均可，但必须 **同一规范点**（推荐：**ANN 后、eligibility 前或后均可接受；推荐 ANN 后立刻切噪声，再跑 eligibility 降 Port 调用**）。

3. **Rerank**

4. **Pool**

#### 推荐 A · 详细规范（冻结意图）

**A1. Request（逻辑最小闭集）**

```text
team_uuid                 # required；服务端强制
query                     # required string；空白 → empty 或 400（推荐：trim 后空 → RETRIEVE_EMPTY）
namespace_key|uuid        # required or default namespace policy
return_k?                 # default 10；1..max_topk
recall_k?                 # default 20；clamp
score_threshold?          # default config 0.0；不得 > 实现 max
filters?                  # Layer B pins；仅注册键；未知 → RETRIEVE_FILTER_INVALID
include_pack?             # default true|false（随 Q5；推荐 default true）
# 禁止：raw query vector、distance_metric、embedding_model override、index_generation（v1）、stream
# 若 Q4=A：禁止 include_answer
```

**A2. Response（逻辑最小闭集）**

```text
disposition: ok | empty | error
results: RetrievalResult[]     # 可空
pack?: PackView                # 若 include_pack
diagnostics: {
  recall_k, return_k, threshold_applied,
  ann_hit_count, eligible_count, filtered_count,
  rerank_status, pack_truncated?,
  empty_reason?: no_hit|all_filtered|below_threshold|blank_query
}
# RetrievalResult: D05 最小字段
#   + ann_score, rerank_score?, score (final),
#   + traceback_status, context_tier, filters_echo,
#   + generation_refs, coordinate, granularity, hit_channel,
#   + hit_content|ref, payload_content|ref
# 禁止：raw embedding、provider secrets、filesystem path
```

**A3. 错误前缀闭集**

| 前缀 | 用途 | 示例 |
|---|---|---|
| `RETRIEVE_*` | 检索域业务/契约 | `RETRIEVE_FILTER_INVALID`, `RETRIEVE_EMPTY`（机读 empty）, `RETRIEVE_TOPK_INVALID` |

| `RETRIEVE_INFERENCE_*` 或透传 | embed/rerank | 与 S11 映射；**SPACE_VIOLATION** non_retryable |
| **禁止** 主用 | `PUBLISH_*` / `INDEX_*` 作 search 主码 | S09 分账 |

S03 **不**介入 search（无 Process）；无 max_retries 账本。
