#### 选项

| 表 | 默认 hot retention | 删除方式 | 与 cleanup 关系 |
|---|---|---|---|

**归档原则（B）**：append-only 不变；仅整段时间窗 DELETE；可选 pre-delete export 到 ops 目录（**非**业务 SSOT / **非**第二事件库）；配置键可经 S14 ops knobs 调整天数但须 **审计事件** `ops.retention_policy_changed`。

#### RECOMMENDED：`B`（+ RC Δ1）

**Reasoning**  
1. 服从 T-O-297：Event/Log retention 与 Process cleanup **分账**；cleanup 不得删 S15 表。  
2. A 导致无限膨胀，与 leaf-worker 本地盘/Turso 成本模型不匹配。  
3. C 过短：security_audit 与跨天排障（P-06 trace 时间线）受损；与 D04「诊断短于 events」方向亦冲突。  
4. D 制造外置事件 SSOT，违反 T-O-288/289（metrics 不进业务库 ≠ 把事件真相迁出库当第二真相）。  
5. B 对齐 D04 建议区间（诊断 7–30 → 取 **14**；events 更长 → **90**；审计更长 → **180**）及行业 hot 惯例（Purview 180d / FedRAMP 90d hot）；整段 DELETE 满足 T-O-291 append-only。  
6. S13 backup **保留份数/排程** 同题钉默认，避免 runbook 真空（T-O-299）。

**内部证据**：T-O-291/292/293/297/299；EC-14/15/24/32/38；D04 §3.1.3–3.1.4；S03-T049；S13-T029；N-03。
