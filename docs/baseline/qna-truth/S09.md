### Q1 — `index.validate_publication` 成功判定与对账算法

- **驱动条件**：`T-O-232/233/236/238` · EC-07/08/23–28 · 考古 N-01/N-05/N-09/P-05  
- **层级**：S09 **执行** · Process 成功边界（不 reopen S08 写侧）  
- **定位**  
  S08 已交付 `VectorizeHandoffV1` +（可能含半写残留的）`mkb_vector_records`。  
  S09 的 `index.validate_publication` 必须定义：**以什么为 expected、以什么为 actual、何时 disposition=成功、半写/软删/跨 generation 如何 fail-closed**。  
- **为什么必须确认**  
  1. 若不独立对账，会重演 legacy「Vectorize 有 id 即可搜」（N-01）。

  4. D01 成功 guard 要求 expected set **validated**（EC-40）。

#### 选项组合

| ID | 选项 | 含义 | 与邻域 | 主要风险 |
|---|---|---|---|---|
| **A** | **Handoff-only** | 只信 `VectorizeHandoffV1.disposition=full_valid` + counts；不扫库 | 弱化 EC-08「Handoff≠Proof」 | Handoff 与库漂移；半写/并发 purge 不可见 |

| **C** | **仅扫库、无 Handoff** | 只按 generation 扫 records | 丢掉 digest 绑定 | 错 generation / 错 model 难防 |
| **D** | **抽样 / 阈值放行** | 部分 unit 即可 publication | 违反整包精神（EC-24/25） | 半包上线 |
| **E** | **合并进 S08 Outcome** | vectorize 成功即 publication | 违反 T-O-221/230/232 | 吞 S09；半写窗口 |

#### 推荐 B · 详细规范（冻结意图 · 待业主确认）

**ProcessCapability**：`index.validate_publication`（独立叶；S03 注册）。

**Command 最低闭集**（materialize 后 `command_input_digest` 冻结）：

### Q3 — IndexGeneration 作用域、多代共存与 rebuild/切流协议

- **驱动条件**：`T-O-234/236/239` · EC-16/17/26/31–34 · 考古 N-02/N-03/N-04 · 风险 R-02/R-03  
- **层级**：S09 **执行** · 代数与 rebuild（不 reopen S04「rebuild 不建 Revision」）  
- **定位**  
  S08 明确 **不**自动 purge 旧 generation（EC-26），故多代向量可物理共存。  
  S09 必须定义：**IndexGeneration 是什么粒度的指针**、**谁 CAS**、**rebuild 如何 build→validate→switch→grace→purge old**、以及与 namespace/record 上 `index_generation` 列的关系。  
- **为什么必须确认**  
  1. R-02：namespace 列 / record 列 / active pointer 三义未统一。  
  2. 考古 N-02/N-03：无 purge 的新 UUID 叠加 = 僵尸可搜。  
  3. S04-T034 已给 rebuild 五段序，但 **index 侧代数与 proof 绑定** 未钉。  
  4. `index.rebuild` scope 是 S01 交给 S09 的空位（EC-04）。

#### 选项组合

| ID | 选项 | 含义 | 多代共存 | 风险 |
|---|---|---|---|---|
| **A** | **无代数；永远 latest 行可搜** | 不引入 IndexGeneration | 全可搜 | 重演僵尸向量（N-03） |
| **B**（推荐） | **Item×Namespace 级 active IndexGeneration 指针 + 行级代数标记** | 每 (team,item,namespace) 一个 CAS active generation；records 带 `index_generation`；publication proof 绑定该代数；rebuild 分配新代数 | 旧代保留直至 grace purge | 需指针存储约定 |
| **C** | **仅 namespace 全局单调计数** | 整 team namespace 一次切流 | 粒度过粗 | 单 item rebuild 误伤全库 |
| **D** | **每次 vectorize 成功自动 purge 同 item 全部旧代** | 写侧隐式切流 | 近似单代 | 违反 S08 G1/EC-26；扩大写侧职责 |
| **E** | **Revision 即 IndexGeneration** | 不设独立指针 | 与「structure rebuild 不改 Revision」冲突场景纠缠 | 混淆 S04/S06 身份 |

#### 推荐 B · 详细规范（冻结意图 · 待业主确认）

**B1. 概念**

```text
IndexGeneration (逻辑)
  = 某 (team_uuid, intake_item_uuid, namespace_uuid) 下的
    单调递增代数（integer），标识「当前被 publication 绑定的向量投影世代」

ActiveIndexPointer
  = CAS 保护的 { item, namespace → active_index_generation, row_revision, proof_ref? }
  存储：优先独立小表或 D04 允许的 pointer 位；
        **不得** 用 intake.serving_revision 冒充；
        **不得** 只用 namespace.index_generation 表达 per-item 切流（namespace 列可作「空间重建」计数，见下）
```

**B2. 与 D04 列对齐**

| 列 | 语义（推荐） |
|---|---|
| `mkb_vector_records.index_generation` | 该行所属 **item 投影代数**（写入时由 S08 默认 0 或由 S09 rebuild 路径赋值；**publication 只认可 active 代数** 或「proof 绑定代数」） |
| `mkb_vector_namespaces.index_generation` | **空间级** rebuild/迁移代数（model/dim 变更、全量 reindex）；≠ item active 指针 |
| ActiveIndexPointer | **S09 SSOT** per (item,namespace) |

**B3. 正常 publication（from vectorize）**

1. 默认：S08 写入的 generation_artifact 对应行，其 `index_generation` = 当前 active **或** 「pending candidate 代数」（二选一在实现细节可定为：  
   - **B3-a（推荐）**：首次 publish 时 active=0 或 1；proof 绑定该代数；  
   - 新 construct+vectorize 产生 **candidate** 代数（active+1）→ validate → CAS active → grace → soft-delete 旧代数行。  
2. 在 active CAS 成功前，S10 **不得** 仅因行存在而召回 candidate（配合 Q1/Q2 谓词）。

**B4. `index.rebuild` 协议（继承 S04-T034 五段）**

```text
scope (Command 必填闭集，至少其一粒度):
  - intake_item_uuid (+ optional revision pin)
  - namespace_uuid
  - optional channel_filter
  - optional generation_artifact_uuid（重建指定 construct 代）

steps:
  1. build: 触发或等待 S08 路径产出 candidate 向量
            （rebuild 不创建 IntakeRevision；可新 construct generation 或 re-embed 策略另轮）
  2. validate: index.validate_publication on candidate
  3. CAS ActiveIndexPointer → candidate generation（expected 旧值匹配）
  4. grace: 配置化窗口；旧代仍物理在、默认不服务
  5. purge old: soft-delete 旧 index_generation 行

fail: 任意步失败 → active 不变；candidate 可保留供重试；不得自动 purge active
```

### Q4 — 可服务谓词闭合与 S04 invalidation / withdraw 执行

- **驱动真相**：`T-O-235/236/241/242/243` · S04-T023/T033/T037 · EC-12/31–35 · 考古 N-01/N-08 · W6/W7  
- **层级**：S09 **执行**（不 reopen S04 意图语义）  
- **定位**  
  Round 1 钉了「如何证明可发布」与代数切流；尚未钉 **S10 读路径最小谓词**，以及 S04 deactivate/delete/CLEAR_SERVING 时 S09 如何 **withdraw 投影 + 配合 CleanupProof**（异步、不反向恢复 serving）。  
- **为什么现在**  
  1. 无闭合谓词，实现者仍可能「ANN 命中即返回」。  
  2. legacy `is_active` 写入却不检索（N-08）。  
  3. tombstone 文献要求 **查询必滤** + delete fast-path。  
  4. S04 四意图已分账，S09 须钉 substrate 侧执行。

#### 选项组合

| ID | 选项 | 含义 | 风险 |
|---|---|---|---|
| **A** | 仅 `deleted_at IS NULL` | 过窄 | candidate/半写/非 active gen 仍可搜 |
| **B**（推荐） | **规范可服务谓词 + invalidation 协议** | 见下 | 实现面中等 |
| **C** | 仅靠 S04 eligibility，索引侧无 filter | 漏围栏 | 违反 dual fence / D04 查询序 |
| **D** | deactivate 时同步 hard-delete 全部向量 | 过激 | 无 grace、与 soft-delete 纪律冲突 |
| **E** | invalidation 只写日志，不改投影 | 假撤 | 继续可搜 |

#### 推荐 B · 详细规范（冻结意图）

**B1. 索引侧「publication-valid candidate」最小谓词（S09 拥有；S10 必须应用）**

```text
team_uuid = :team
AND deleted_at IS NULL
AND publication_state = 'indexed'          -- 非 withdrawn
AND namespace_uuid 匹配且 namespace.status = active
AND embedding_model / dimension 匹配 query Layer A
AND index_generation = ActiveIndexPointer.active  -- 该 item×namespace
AND intake_item_uuid / intake_revision_uuid 满足调用方 pin
-- 然后才进入 S04 IntakeEligibilityPort（lifecycle + serving_revision）
-- 禁止：仅 ANN 命中返回
```

**B2. Invalidation 触发（消费 S04 意图，不发明 lifecycle）**

| S04 意图 | S09 执行（异步可） | 不做什么 |
|---|---|---|
| CLEAR_SERVING / deactivate | 本 item 相关 active 集：`publication_state→withdrawn` **或** 立即不可过 B1（二选一推荐：**withdrawn**）；可选 enqueue grace soft-delete | 不改 Item 状态；不恢复 serving |
| delete + tombstone | withdrawn + 进入 CleanupIntent 队列；soft-delete 行；CleanupProof 提交 S04 | 不因部分失败恢复 serving |
| rebuild | 走 T-O-243 五段；旧代 retiring | 不创建 Revision |
| physical_purge | 仅在 S04 eligibility 后物理回收（S15 天数） | 默认路径不 hard-delete |

**B3. 并发**

- 正在 `validating` 的 candidate：S04 CLEAR 到达 → **中止或 fail** publication（expected pointer 不符），不 promote。  
- active CAS 与 withdraw：**CAS 期望代数**；冲突 fail-loud 重试。

**B4. 事件（低基数）**

- `index.withdrawn` / `index.generation_retired` / `index.cleanup_proof_submitted`（名称可微调；S15 拥有保留策略）。

#### Reasoning

1. D04 已规定 ANN→关系 filter→eligibility；B1 是可编码落地。  
2. W6/W7：tombstone 必须 query filter + delete 要有快路径，但 **hard-delete 非默认同路径**。  
3. A/C 重演 N-01；D 破坏 grace/T-O-243；E 假撤。  
4. 不夺取 S04：只执行 substrate 投影与 proof 提交。

#### Supporting evidence

| 类型 | 引用 |
|---|---|
| Baseline | T-O-235/242/243；S04-T023/T033/T037；D04 §3.7.3 |
| Legacy | N-01 存在即搜；N-08 is_active 无效 |
| Web | W6 tombstone；W7 delete fast-path；W2 勿 partial serve |

#### 业主回答

业主 **接受推荐 B**（2026-08-12）：publication-valid 谓词闭合 + S04 invalidation 投影/withdraw 协议。

### Q5 — ANN metric / topK 默认与 S10 查询分账

- **驱动真相**：`T-O-231/234` · D04 `distance_metric` CHECK · G-09 余量 · EC-16/19 · W3/W8

  1. G-09 算法余量仍 open。

#### 选项组合

| ID | 选项 | 含义 | 风险 |

| **C** | S09 钉死查询 topK 与 threshold，S10 不可改 | 过僵 | 产品检索无法调 |
| **D** | 每请求任意 metric 切换 | 混空 | 违反 Layer A / 距离不可比 |
| **E** | v1 禁用 ANN，仅 exact brute force | 与 D04「ANN 强制存在」张力 | 性能与 G-09 部分合同冲突 |

#### 推荐 B · 详细规范（冻结意图）

**B1. Namespace / 空间默认（S09 登记，bootstrap 写入 `mkb_vector_namespaces`）**

| 参数 | v1 默认 | 规则 |
|---|---|---|

| embedding space | Command/namespace model+dim | 与 S11 Layer A 一致 |
| ANN 参数（ef/lists 等） | **引擎安全默认** + 配置项 | 缺失不阻塞「index 存在」readiness；调优归运维配置 / S14 可版本化 |

**B2. topK 分账**

| 层 | Owner | 规则 |
|---|---|---|
| **Index hard cap** | **S09** | `max_topk` 配置化（建议默认上限 **100**；可配置，**硬顶**防 OOM） |
| **Default topK（未指定时）** | **S09** 提供库默认 **10**（与 legacy 同量级仅作默认，非产品真理） | S10 可在 Command/API 覆盖，但 ≤ hard cap |
| **Score threshold / 业务裁剪** | **S10** | 如 0.65 类阈值、diversify、channel 策略 |
| **Rerank topN** | **S10** | 不在 S09 |

**B3. Query 合同（S09 只定义索引端口；S10 调用）**

```text
VectorSearchRequest:
  team_uuid, namespace_uuid | namespace_key
  query_embedding (dim must match)
  top_k: 1..max_topk
  filters: Layer B pins (team 强制)

# 禁止：客户端自选 distance_metric 覆盖 namespace
# 禁止：跳过 B1 谓词（Q4）
```

1. D04 已默认 cosine + ANN 存在 → A/E 不合适。  
2. B 解决 R-06：S09 cap/default，S10 策略。  
3. D 混 metric 是 W3 点名事故。  
4. C 让 S10 无法做产品检索调参。
