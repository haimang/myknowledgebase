### Q1 — Token mint 主体与物理载体

| 项 | 内容 |
|---|---|
| **标题** | 谁签发内部 token？物理形态是 shared secret header、mTLS 还是短时签名 JWT？at-rest 如何存？ |
| **Impact** | 全部业务/ops 面的信任根；运维复杂度；是否滑向 IdP/session 平台 |
| **Why must decide** | S01-E09 / EC-17 只钉 valid/invalid 口径与「载体归 S16」；EC-02 强制回答 mint 主体；T-O-313 禁平台 RBAC/session |

#### 选项

| 选项 | 摘要 | 要点 |
|---|---|---|
| **A** | **mTLS 客户端证书为唯一认证** | 证书身份；无 bearer secret；部署重、与 S01「简单 token」叙事偏离 |
| **B** | **Shared secret 内部 token（header）+ ops mint + at-rest 仅 hash（推荐）** | 见下规范意图 |
| **C** | **短时签名 JWT（含 user/team/role/plan claims）** | 平台 auth 回潮；N-01 反例 |
| **D** | **每请求外部 Vault 动态签发为唯一产品路径** | 强制依赖外部 IdP/Vault 产品；leaf 过重；可作为未来可选增强非 v1 默认 |

#### 选项 B 规范意图

| 项 | v1 规则 |
|---|---|
| **Mint 主体** | **运维 / 部署者**（ops）在受控环境生成高熵随机 token；MKB 进程 **不** 暴露公网「self-service mint API」；**不** 建用户注册/登录 |
| **载体** | HTTP header：`Authorization: Bearer <token>` **或** 固定 `X-MKB-Internal-Token: <token>`（二选一主路径 formal 钉；另一兼容可选） |
| **语义** | 仅 **valid / invalid**（T-O-313）；**无** membership / team / role claim；与 `team_uuid` 请求字段 **正交** |
| **At-rest** | 配置/密钥仓中仅存 **SHA-256（或更强）指纹集合**；明文 **只** 在 mint 交付通道出现一次（P-01/P-02） |
| **Compare** | **timing-safe** 恒定时间比较（P-03 思想） |
| **进程加载** | 启动时从 L2 env / 部署 secret 注入 **当前 active 明文集**（对比用）或 **hash 集 + 运行时 hash(input)**；明文 **永不** 写 DB 业务列 / security_audit payload |
| **Actor** | 校验成功 → `actor_kind=internal_token`；`actor_fingerprint=H(token)`（D04） |
| **禁止** | login/session/refresh；JWT user claims；team-scoped API key 产品（N-02）；token 明文进 log/event |

#### RECOMMENDED：`B`

**Reasoning**  
1. 直接服从 OD-05 / S01-T046 / T-O-313：简单内部 token，非 IdP。  
2. C 完整复刻 N-01 平台 JWT；D 把 leaf-worker 绑死 Vault 产品，违背 OD-01 简单性。  
3. A 可作未来 **叠加** 网络层，但 v1 契约与 S01 语言是「token」，mTLS-only 会迫使上游协议大改且不回答 header 审计指纹。  
4. B 吸收 P-01/P-02/P-03（hash、展示一次、timing-safe），与 D04 `actor_fingerprint` 天然对齐。  
5. Mint 归 ops 而非应用内 self-service，避免 N-03 用户平台。

**内部证据**：T-O-313/314/316；EC-11/16/17/24；S01-T046/E09；S01-A01/A02；P-01/P-02/P-03；N-01/N-02/N-03/N-12。

**残差风险**：多副本部署须同步 active secret 集（靠 Q2 重叠窗缓解）；header 名最终 formal 二选一需与 S01 OpenAPI 校准；mTLS 可作为 **部署可选加固** 不改变应用层 valid/invalid。

**RC 注记**：`completed / step 3` · **维持 B** · **Δ1**（§5.1/§5.12）：高熵 token 可 SHA-256 at-rest；timing-safe compare；mTLS 仅部署可选网络加固不改 valid/invalid 应用层；禁 JWT claims 平台。

**Owner 裁决**：`🔒 workflow-frozen / RC-adjusted recommendation B → T-O-327`

### Q2 — Rotation、dual-active 重叠与吊销

| 项 | 内容 |
|---|---|
| **标题** | 内部 token 如何轮换？是否 dual-token 窗口？如何紧急吊销？ |
| **Impact** | 密钥泄漏响应时间、滚动部署零中断、是否滑向 refresh-token 平台 |
| **Why must decide** | EC-02/17 要求回答轮换；OD-05 禁「token 生命周期 **平台**」但仍需最小运维策略 |

#### 选项

| 选项 | 摘要 | 要点 |
|---|---|---|
| **A** | **不支持轮换**：只能全停换 env 重启 | 最简；泄漏/滚动时强制中断 |
| **B** | **Dual-active 重叠窗 + ops 滚动 + 显式吊销（推荐）** | 见下规范意图 |
| **C** | **OAuth refresh / 会话吊销产品** | 平台生命周期；OD-05/N-03 |

#### 选项 B 规范意图

| 项 | v1 规则 |
|---|---|
| **Active 集合** | 进程内 **最多 N 个** 同时 valid 的 token 指纹（默认 **N=2**：current + previous） |
| **重叠窗** | 运维引入 new token 后，old 在可配置重叠期内仍 valid（默认建议 **24h**，ops knob，不进 binding_digest） |
| **滚动步骤** | (1) 生成 new → (2) 注入 active 集（env/文件热载或滚动重启）→ (3) 上游改用 new → (4) 重叠结束 drop old |
| **热载** | 允许 **ops-only** 信号/管理 hook 重载 active token 集（失败 → last-good + 告警；**不** 改业务 binding） |

### Q5 — Replay 边界（传输层 vs 业务幂等）

| 项 | 内容 |
|---|---|
| **标题** | 除业务幂等外，是否强制请求 nonce/timestamp 防重放？ |
| **Impact** | 协议复杂度、时钟同步、与 S01 Task Create 幂等分账 |

#### 选项

| 选项 | 摘要 | 要点 |
|---|---|---|

**内部证据**：T-O-322/324/325；EC-14/23；S01 idempotency/canonicalization；S02；G-02。

**残差风险**：若未来公网暴露，须 reopen 传输层签名；时钟攻击不在 v1 模型内。

**RC 注记**：`completed / step 3` · **维持 B** · **Δ5**（§5.5/§5.12）：业务幂等权威（Stripe 式 Idempotency-Key 思想可复用 S02 已有字段）；**不**强制 HMAC/nonce 传输产品；公网威胁模型 reopen 时再评估。

### Q6 — Egress / SSRF 全局宪法

| 选项 | 摘要 | 要点 |
|---|---|---|
| **A** | **https-only 即可，无 host 策略** | 实现最简；**不**防 SSRF 到 https metadata 变体/内网 |

#### 选项 B 规范意图

| 规则 | v1 |
|---|---|
| **默认** | 业务出站 **deny unless allowed**（fail-closed） |
| **硬拒绝目标** | link-local（`169.254.0.0/16` 等）、loopback、RFC1918 私网（**除非**显式 profile 声明 internal-only source 且部署策略允许）、云 metadata host 名/路径惯例、字面 IP 直连绕过（策略可配置但默认拒） |

| **失败** | policy 失败 **fail-closed**（EC-42）；写 security_audit 当属 admission/安全拒绝时 |

**Reasoning**

**残差风险**：合法「拉内网企业源」需显式 profile——默认拒可能 initially 摩擦；DNS rebinding 需 formal 实现注意（先 resolve 再校验 IP）。

**RC 注记**：`completed / step 3` · **维持 B** · **Δ6**（§5.6/§5.12）：**DNS rebinding 防御**（resolve 后校验 IP 再连接）；redirect **默认 ≤3 且每跳重跑策略**；prefer allowlist（S05）+ 硬拒网段 denylist 双层；禁 open proxy。

#### 选项 B 规范意图

##### B.1 错误码闭集（typed · 可 formal 微调名）

| Code | 含义 | HTTP 映射（业务面） |
|---|---|---|
| `SEC_TOKEN_MISSING` | 无 token | 401 |
| `SEC_TOKEN_INVALID` | token 无效/已吊销 | 401 |
| `SEC_RATE_LIMITED` | 限流 | 429 |
| `SEC_RATE_LIMITER_DEGRADED` | 限流器故障（metric/ops；通常不替代业务码） | — |
| `SEC_EGRESS_DENIED` | 出站策略拒绝 | 4xx/domain 映射 |
| `SEC_EGRESS_REDIRECT_DENIED` | redirect 目标非法 | 同上 |
| `SEC_SECRET_UNRESOLVED` | slot 无法解析 | fail-closed 5xx/domain |
| `SEC_SUPPLY_UNBOUND` | 未绑定 catalog/binding | fail-closed |
| `SEC_MODEL_ENDPOINT_REJECTED` | 非法 model endpoint | fail-closed |
| `SEC_PATH_REJECTED` | path/handle 安全拒绝 | 4xx |
| `SEC_TEAM_SCOPE_VIOLATION` | 跨 team / 缺 team 围栏 | 403/404 策略服从 S02（**不**用 team 当 auth 成功条件） |

##### B.2 security_audit 写语义（S16 主责）

| 规则 | v1 |
|---|---|
| **必须写** | `outcome=denied` 的 admission/安全拒绝（认证失败、跨 trust 边界、egress 安全拒绝等「未进业务表」） |
