#### 推荐 B · 投递语义（业内对齐 · 冻结意图）

| 规则 | 说明 |
|---|---|
| **同 TX 入队** | construct full_valid CAS 与 `vectorize_construct` outbox **同一业务事务**（Transactional Outbox） |
| **at-least-once** | outbox relay / claim **不保证** exactly-once；允许重复投递 |

2. **Transactional Outbox 正例**：业务写与「待投递消息」必须同库同事务，否则双写分裂（业务成功无唤醒 / 唤醒了业务未提交）。

   - AWS Prescriptive Guidance · Transactional outbox：<https://docs.aws.amazon.com/prescriptive-guidance/latest/cloud-design-patterns/transactional-outbox.html>  
3. **at-least-once → 消费侧幂等（正例）**：AWS 明确 outbox/SQS 类投递会重复，消费服务须 idempotent。B 用 Command digest + record upsert 承接，而非 A 的「消息工人即真相」。

### Q5 — 整包二元下的批处理、渐进 upsert 与最终证明

- **驱动真相**：`T-O-222` · `T-O-223` · `T-O-218` · S11-E09
- **影响范围**：S08 主循环；S11 并发闸；S12 TX 粒度；S15 进度指标
- **定位**  
  整包成败已锁，但 **未锁**：  
  1. 单 Process 内 unit 是串行还是有界并发 batch；  
  2. 是否允许 **渐进 upsert**（每 unit 一 TX）再最终 gate，还是全部 embed 完单 TX 提交；  
  3. 失败时已写行策略（保留幂等 vs 回滚）；  
  4. 进度可观测是否进入 Outcome/domain_events（非 StateFamily）。
- **为什么必须确认**  
  大文档 required 可达数千 unit；策略决定 lease 心跳、S11 闸、以及「半写可见性」风险（反方制衡 §5.3）。

#### 选项组合

| ID | 选项 | 处理 | 提交 | 失败 | 评价 |
|---|---|---|---|---|---|
| **A** | 全量内存 embed 后单 TX 写入 | 串行/批 embed | 单 TX all-or-nothing | 自然无半写 | 大文档内存/lease；embed 已付费却整包回滚 |
| **B**（推荐） | **有界 batch + 渐进幂等 upsert + 最终 full_valid gate** | batch 配置化 + 可选 bisect；稳定 unit 序 | **每成功 unit/小批 upsert**；全 required 完才 Outcome success | 失败 → failed；**保留**已写行供幂等重试；**不** publication | 生产主流；依赖 T-O-219 |
| **C** | 失败时补偿删除本 process 已写行 | 同 B | 同 B | 尽力 delete | 与幂等重试冲突；难原子 |
| **D** | unit 级子 Process | N claim | — | 违反 Q2 | **禁止** |

#### 推荐 B 细节（可编码）

1. **稳定枚举序**：generation 内 unit 按 `(granularity, unit_id, channel)` 字典序（Spec 钉死）。  
2. **有界 batch**：`vectorize.max_embed_batch_items` / token budget 配置；默认服从 S11 闸；**非** Truth 绝对数。  
3. **provider 拒绝 / 超限**：允许 **缩小 batch / bisect 重试**（transport 内环归 S11；不计入 Process `retry_count` 直至内环耗尽）。  
4. **最终 gate**：`succeeded_units == required_units` 且 failed 空 → `full_valid`；否则 failed。  
5. **失败不补偿删**：已写行保留；同键重试 **upsert 覆盖**。  
6. **半写不可服务**：未 `full_valid` **禁止** S09 publication（T-O-219）。  
7. **可选短路**：同 `(unique key)` 且 `content_digest`+model 已匹配 → 可 skip re-embed，仍计 required 完成。  
8. **事件**：可选低基数 `vector.unit_upserted`；**禁止**事件当成功 SSOT。  
9. **lease**：长跑 heartbeat（S03）。

#### Reasoning / Evidence（含业内 Reference-Check）

1. **确定性键 + 幂等 upsert（正例）**：生产级迁移与向量库均强调「同业务键再写 = 覆盖」，使重试/重投递/backfill 安全。  
   - Meltwater · Re-homing 185M embeddings（确定性 key → idempotent PutVectors；resume 靠幂等而非完美回滚）：<https://underthehood.meltwater.com/blog/2026/08/06/re-homing-vector-embeddings/>  
   - Qdrant · Idempotence（同 id 覆盖；适配 at-least-once 队列）：<https://qdrant.tech/documentation/manage-data/points/>  
   - Pinecone 社区：identical IDs overwrite on upsert。  
2. **有界 batch + 失败拆批（正例）**：Meltwater 对 embed provider 硬 token 限用 **submit-then-bisect**（估计仅作提示，正确性靠拒绝后拆半），反对「一次估准塞满」。支持 B 的有界批 + 可拆，反对 A 的全量内存单提交。  
3. **partial failure 必须 track 单条成功（正例）**：流式/批处理文献指出 999 成功 1 失败时，若不记录单条状态会丢 1 条或重复 999；正确路径是 **幂等 + 记录进度/可安全重放**。
